# Базовые принципы именования endpointow

1. Использовать существительные во множ. числе

```
правильно: /users, не правильно: /getUsers
```

2. Использовать вложенность для связей ресурсов

```
пример: /users/{userId}/orders (получение пользовательских заказов)
```

3. Использовать cebabCase для сложных названий (/словоСловоСлово)

```
userItems, userNames
```

4. Избегать лишних слов (не добавлять глаголы, если этого не требуется)

```
пример: /products, а не: /getProducts
```

# Как выбрать HTTP метод

1. create(Создать) => POST => создаёт новый ресурс. Используется когда у ресурса нет id (за исключением иерархической вложенности)

2. получить => GET => возвращает данные, не изменяя ресурсы, а также содержит quary параметры

```
GET/users?id=2; GET/users?filters={status:"active"}
(все, что после вопросительного знака содержит имя и последующий знак равн
является quary параметром. Если quary параметр содержит фигурные скобки,
значит он является JSON форматом)
```

3. Обновить (изменить) => PUT или PATCH => обновляет существующий ресурс. PUT - полная замена, PATCH - частичное обновление.

```
Пример:
PUT/users/{userId}/avates
PATCH/users/{userId}/setings
```

4. Удалить => DELETE => удаляет или помечает как удалённый ресурс по id

```
DELETE/items/{itemId}
```

# Когда использовать quary параметры

1. Нужно фильтровать, сортировать или искать по данным

2. Передача необяз. параметров

```
Например: ключ сортировки
?sortKey=1
?sort="ASС"
?sort="DESC"
GET/products?name="DESC" (если написано name ключевое слово ASС и DESC)
GET/products?sort={name=DESC; price=ASC;};
GET/products?page=1&limit=50
(page - страница, limit - кол-во эллементов на странице)
```

3. Передача данных, которые не является частью идентификатора ресурсов

```
GET/search?q=Android
```

4. Когда использовать POST параметры

```
POST параметры - это часть url в фигурных скобках
POST/items/{itemId}/upload
```

- Необходимо указать обязательный идентификатор ресурсов

```
например: в методах POST, PUT, PATCH или DELETE
```

- Реализация иерархической связи ресурсов

```
POST/users/{userId}/photo
```

5. Когда использовать body (тело запроса)

- в случае передачи данных, которые требуют шифрования

- при передачи большого кол-ва данных

```
например: массив или объект
```

- в методах POST, PUT, PATCH

```
body представляет из себя JSON объект, приведённый к строковому представлению
```
